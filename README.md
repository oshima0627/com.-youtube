## 使い方

```bash
python -m clipper run <video_id>          # 素材確認→信号→候補→ゲート→書き出し
python -m clipper candidates <video_id>   # 候補だけ見る
python -m clipper held                    # 保留されたクリップと理由
python -m clipper status                  # 全体の状態
```

書き出しは `out/`、中間物は `work/`。どちらも git では追跡しない。
追跡するのは `data/videos/<video_id>.json` の台帳だけで、何をいつ作り、
何を保留にしてなぜかがコミット履歴に残る。権利者から問い合わせが来たときに
提示できる記録はこれ。

## 切り抜き地点の探し方

先行プロジェクト `tora-kirinuki`（令和の虎の切り抜き）から4信号の合成方式を
移植したが、**そのままでは効かなかった。** ヒートマップのある4本を正解にして
測り直した結果が以下（詳細は [`docs/signal-evaluation.md`](docs/signal-evaluation.md)）。

| 信号 | 上位3平均/基準線 | 正解を当てた本数 | 扱い |
| --- | ---: | ---: | --- |
| コメントの時刻言及 | **1.97倍** | **2/4** | 主軸 |
| 字幕の語彙・効果音タグ | 1.17倍 | 0/4 | 同点崩しのみ |
| 音量スパイク | 0.70倍 | 0/4 | **無効**（`W_LOUD=0`） |
| ヒートマップ | — | — | あれば加点。公開24日未満では存在しない |

**音量は効かない。** 令和の虎は虎が怒鳴るので音量が盛り上がりに直結するが、
コムドットは5人が常時にぎやかで音量の分散が小さく、スパイクが場面の質を示さない。
`W_LOUD` を 0 にしただけでは同時加点（`COMBO_BONUS`）が裏口から効いていたため、
そちらも 0 にしてある。

**ヒートマップは主軸にできない。** コムドット12本を実測したところ、公開24日未満の
8本には存在せず、24日以上の4本にのみ存在した（全12本が再生50万回超なので効いて
いるのは経過日数のみ）。切り抜きは新着を早く出すのが勝ち筋なので、一番使いたい
場面で使えない。一方コメントの時刻言及は**公開4日でも42箇所**あり、新着で使える。

## 素材にしてはいけない動画

`screen.py` と `gate.py` が機械的に弾く。

- **メンバーシップ限定動画**（有料コンテンツ。通常の切り抜きより格段に重い違反）
- 概要欄に「出演してくれたクリエイター」等を含むコラボ回
  — **タイトルだけの判定では素通りする。** 実際にCDFシャッフルコラボ週の動画が
  タイトルに手がかりを持たず、概要欄で初めて判別できた
- 概要欄に「提供」「タイアップ」等を含む案件回
- イベント回、災害への言及を含む回、揉め事の文脈

## 書き出しの注意

**本編に字幕が焼き込まれているため、こちらで字幕を足すと二重になる。**
`render_short` / `render_wide` の字幕焼き込みは既定で無効。

**横型を複数区間の連結で作らない。** 権利者ガイドラインの一般的な要求として
分割本編の連結禁止がある。1本の連続区間だけを切り出す。
