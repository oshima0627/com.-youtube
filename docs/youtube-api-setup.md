## なぜ専用プロジェクトが要るか

**API のクォータは Google Cloud プロジェクト単位で配られる。** 既定は 10,000ユニット/日で、
`videos.insert` が 1,600 と重いため、実質アップロード6本/日が上限。

`tora-kirinuki`（令和の虎の切り抜き）の OAuth クライアントを流用した結果、
2026-08-14 にこのチャンネルで 403 `quotaExceeded` が出た。向こうが前日に
10本上げて使い切っていたため。**クライアントを共有するとクォータも共有される。**

超過すると `channels.list`（1ユニット）すら通らず、状態の確認すらできなくなる。
回復は太平洋時間の0時（JSTの16〜17時ごろ）で、日本時間の日付が変わっても戻らない。

## 手順

1. <https://console.cloud.google.com/> で**新しいプロジェクトを作る**
   （現行は `comdot-meibamen`。既存プロジェクトを選ばないこと）
2. 「APIとサービス」→「ライブラリ」→ **YouTube Data API v3** を有効化
3. 「OAuth 同意画面」を設定
   - User Type: **外部**
   - スコープに `youtube.upload` / `youtube.readonly` / `youtube.force-ssl` を追加
   - **テストユーザーに投稿用アカウントを追加する**（`orfevre6.27@gmail.com`）
4. 「認証情報」→「認証情報を作成」→ **OAuth クライアント ID**
   - アプリケーションの種類: **デスクトップアプリ**
5. JSON をダウンロードし、`client_secret.json` としてリポジトリ直下に置く
6. 古いトークンを消して認証し直す

```powershell
Remove-Item token.json
python -m clipper auth
```

**同意画面では必ず「コムドット名場面ch【切り抜き】」を選ぶ。** 同じアカウントに
「日本の最新ニュースまとめ」「図解でわかる令和の虎」がある。アカウントを選んだだけでは
足りず、表示されるチャンネル名を確認すること。

`auth` が `UCoT2TYsxzH4t42C2oF-KrAw` を表示すれば正しい。違う ID が出たら
`token.json` を消してやり直す。`config/settings.yaml` の `expected_channel_id` と
一致しない限りアップロードは実行されない。

## チャンネルの電話番号確認ができていない

2026-08-14 時点で、使える電話番号が別のアカウントで既に使われているため
このチャンネルの確認ができない。影響は2つ。

**1. カスタムサムネイルが設定できない。** `thumbnails.set` が 403 `forbidden` を返す。
`config/settings.yaml` の `channel.custom_thumbnails` を `false` にして
API を叩かないようにしてある。画像自体は毎回生成しているので、確認が
できるようになったら `true` に戻すだけで設定できる。

実害は小さい。ショートはフィードで動画フレームが使われ、こちらの動画は
1フレーム目に見出しのオーバーレイが乗っているため、自動生成のサムネイルが
実質こちらの設計した絵になる。

**2. 15分を超える動画を投稿できない。** これは効いてくる。tora-kirinuki の
市場調査では、切り抜きの長尺は 13〜20分 が主流だった。確認ができないと
その帯に出せず、**長尺は15分未満に制限される。** 長尺へ広げるときに
再検討が要る。

## リフレッシュトークンの寿命

**7日で失効するのは同意画面が「テスト中」のときだけ。**
`comdot-meibamen` は **2026-09-03 に「本番環境」へ公開したので、当てはまらない。**

```
Google Auth Platform → 対象（オーディエンス）   ※2026-09-03 に画面で確認
  公開ステータス : 本番環境        ← 「テストに戻る」ボタンが出ている状態
  ユーザーの種類 : 外部
  ユーザー数の上限 : 1人 / 100
```

### 公開するために必要だったもの（実測）

「アプリを公開」ボタンは最初は無効で、「アプリの OAuth 構成が完了していません」と出る。
ブランディングの次の2つを埋めると有効になった。

| 項目 | 入れた値 |
| --- | --- |
| アプリケーションのホームページ | `https://github.com/oshima0627/com.-youtube` |
| アプリケーション プライバシー ポリシー リンク | `https://github.com/oshima0627/com.-youtube/blob/main/PRIVACY.md` |
| 承認済みドメイン | `github.com` |

**利用規約のリンクは不要**（必須マークが無い）。

**Search Console でのドメイン検証は求められなかった。** URL だけ入れると
「次のドメインが見つかりません: github.com」と出るので、承認済みドメインに
`github.com` を追加して保存すれば通る。検証は「アプリの確認（verification）」を
申請するときに要るもので、公開そのものには要らない。

プライバシーポリシーの実体はリポジトリ直下の [`PRIVACY.md`](../PRIVACY.md)。
**内容を変えたらこのファイルを更新する**（同意画面からリンクされている）。

### 公開したあとにトークンを取り直すこと

**「テスト中」に発行したリフレッシュトークンには7日の期限が刻まれている。**
公開しても既存のトークンは延命されないので、公開後に取り直す。
2026-09-03 の公開後に取り直し済み。

### それでも失効しうる条件（Google の一般的な仕様。こちらでは未実測）

| 条件 | 対策 |
| --- | --- |
| 6ヶ月間まったく使わない | 日次で投稿していれば起きない |
| Google アカウントのパスワード変更 | 変えたら取り直す |
| ユーザーがアクセス権を取り消す | 取り消さない |
| 同一クライアント×アカウントで発行数が上限を超える | 認証をやり直しすぎない |

## クォータの目安

| 操作 | ユニット |
| --- | ---: |
| `videos.insert`（アップロード） | 1,600 |
| `thumbnails.set` | 50 |
| `videos.update`（公開切り替え） | 50 |
| `videos.list` / `channels.list`（確認） | 1 |

1日 10,000 ユニット。**アップロード6本で 9,600。** 日次1〜2本の運用なら余裕がある。
