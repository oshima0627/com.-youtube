# tora-kirinuki からの転用可能な知見

調査日 2026-08-14。対象 `C:\Users\oshim\Documents\projects\tora-kirinuki`
（令和の虎Second の切り抜きチャンネル `@reiwanotora-second2` を運用するパイプライン）。

先行プロジェクトが実運用で得た結論のうち、コムドット側に効くものだけを写す。
数字は全て向こうの実測か、こちらで取り直した実測。

## 1. ヒートマップは主軸にできない（最重要）

向こうの実測は「令和の虎Second 直近30本中7本（23%）にしか存在しない。
条件は再生5万回以上かつ公開3週間以上」。

**コムドットでも同じことが起きるかを取り直した（12本、2026-08-14）。**

| 公開からの日数 | heatmap | 本数 |
| --- | --- | ---: |
| 4 / 9 / 17 / 19 / 20 / 21 / 22 / 23 日 | なし | 8 |
| 25 / 41 / 53 / 63 日 | あり | 4 |

12本すべてが再生50万回超だったので、**効いているのは経過日数だけ**。
境界は23日と24日の間にあり、令和の虎側の推定（3週間）よりわずかに遅い。

結論として、`clipper/heatmap.py` を一次情報に置いた現在の extract は
**公開24日未満の動画では候補ゼロになる**。切り抜きは新着を早く出すのが
勝ち筋なので、この状態は使いものにならない。過去回を掘るときの加点に降格する。

## 2. 代わりに使う信号（tora-kirinuki の合成方式）

常に取れる信号を主軸にして合成する。実装は `scripts/signals.py` と `scripts/moments.py`。

| 信号 | 常時取得 | 性質 |
| --- | --- | --- |
| 音量スパイク | ○ | 量は多いがノイズも多い。最大スパイクが笑い声のこともある |
| 字幕の語彙 | ○ | 番組構造が定型なら強い |
| コメントのタイムスタンプ言及 | ほぼ○ | 件数は少ないが精度が高い |
| ヒートマップ | 23〜33% | あれば加点 |

設計上まねる価値があるのは、単純加算にしていない点。

- **音量は絶対値でなく局所中央値からの乖離**で見る（前後120秒の median との差）。
  全体が大きい動画でも小さい動画でも同じ尺度になる
- **音量と「詰め」語彙が10秒以内に同時に立つ箇所に加点**する。
  片方だけなら笑い声か単なる言い回しの可能性が残るため
- 信号は点ではなく**前後8秒に三角窓で広げて**足す。字幕とコメントの秒がずれても拾える
- 区間の端は**最寄りの字幕キュー境界にスナップ**する。文の途中で切らない

### コムドットに移すときの相違点

語彙辞書 `LEXICON` は令和の虎の「詰め／金額／判定」という番組構造に依存している。
コムドットにこの構造は無いので、そのままでは使えない。
コムドット側で常時取れるのは**音量スパイク**と**コメントのタイムスタンプ言及**の2つ。
語彙は作り直しになる。

## 3. スコアだけで選ぶと偏る

向こうは最初の8本すべてが動画の平均79%地点＝終盤の判定パートからの切り出しになり、
うち6本が同じ型（完全ALLの成功譚）になった。一方その市場で伸びていたのは中盤の対立だった。

対策として、候補一覧に**スコアだけでなく「動画全体の何%地点か」と「信号の内訳」を出す**。
最終的な選択は人が行う。コムドット側でも同じ罠がある（音量だけで選ぶと絶叫や
効果音の箇所に寄る）ので、内訳の提示は移植する。

## 4. 尺の実測値

- **長尺は13〜20分。** 「令和の虎 切り抜き」検索上位25本はすべて14〜70分。
  当初の420秒（7分）は明確に短すぎた
- **ショートは60〜70秒。** 伸びている競合が67〜73秒。
  向こうの103秒・132秒版は0〜2再生だった

こちらが今日作ったコムドットのショートは39.2秒と57秒で、下限側に寄っている。

## 5. 権利まわりの違い（そのまま持ち込めない）

令和の虎には**公式の切り抜きガイドラインと申請フォームがあり、申請が受理されている**。
コムドットには成文ガイドラインが無く、こちらは問い合わせの回答待ち。前提が違う。

ただし向こうが課されている条件は、こちらでも守って損がない。

- 概要欄に元動画へのリンクを必須にする
- チャンネル名に「切り抜き」を明記する
- **「公式」「公認」と書かない**（権利者の立場は「黙認」）
- ロゴをアイコン・バナー・サムネ・動画内に使わない
- **分割された本編を連結した投稿をしない**（1本の連続区間だけ切り出す）
- 出演者の名誉・信用を害する編集をしない
- 収益化したら権利者へ連絡する

現在のこちらの `render` は1本の連続区間しか扱わないので、連結禁止は満たしている。
横型を「複数区間をつなぐ」設計にしようとしていたが、**この方針は取り下げる**。

## 6. 運用の制約

YouTube Data API の既定クォータは 10,000ユニット/日。`videos.insert` が1,600、
`thumbnails.set` が50。**実質アップロード6本/日が上限。**
超過すると `videos.list`（1ユニット）すら通らず確認もできなくなる。
回復は太平洋時間の0時（JST 16〜17時）。予約公開はサーバー側で動くのでクォータと無関係。

## 7. 転用にあたっての警告

**tora-kirinuki は技術的には完成しているが、成果は出ていない。**
2026-08-13 時点で公開8本（長尺4・ショート4）に対し総再生4回・登録者0。
動画側の異常（リジェクト、地域制限、Content ID、ショート判定）は潰し済みで、
「壊れてはおらず単に露出が出ていない」状態。原因は未特定のまま。

したがって、このパイプラインの**作り方は写す価値があるが、成果が出る保証にはならない**。
特に尺・タイトルの型・投稿時刻といった調整項目は、向こうでもまだ効果が検証されていない。
こちらで採用するときは「向こうでうまくいったから」ではなく、
こちらで測り直す前提で入れること。
